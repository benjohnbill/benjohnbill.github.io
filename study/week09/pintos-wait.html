Pintos의 wait():
부모는 어떻게 자식의 종료를 기다리는가?

자식 스레드를 만들었다고, 자식의 실행이 끝난 것은 아니다.

시작 코드 · run_task()

process_wait(process_create_initd(task));
안쪽 호출: 자식 생성바깥 호출: 종료 대기
threads/init.c · run_task()01 / 도입

안녕하세요. 이번에는 부모가 자식의 종료를 기다리는 wait를 구현한 과정을 이야기하겠습니다. 자식 스레드를 만들었다고 실행까지 끝난 건 아니어서, 부모가 종료를 기다리는 처리가 필요했습니다.

구현 과정 / 기다림의 변화

▸2종료를 알려주는 연결이 필요했습니다.

구조체: include/userprog/process.h · 스레드 필드: include/threads/thread.h03 / 전개

그래서 부모와 자식이 함께 보는 종료 기록인 child_status를 두었습니다. 부모는 children 목록에서 자식의 기록을 찾고, 자식도 같은 기록을 가리킵니다. 여기에 종료 값과 종료 알림을 주고받는 도구인 세마포어를 담았습니다.

근거: process_create_initd()의 malloc, exit_sema 0 초기화, children 등록과 initd()의 child_status 포인터 대입. 구조체는 process.h에 정의되어 있습니다.

userprog/process.c · threads/synch.c04 / 전환

부모는 sema_down으로 종료 알림을 기다립니다. 알림이 없으면 실행을 멈추고 잠듭니다.

▸1자식은 종료 값을 기록하고 자원을 정리한 뒤,

▸2sema_up으로 부모에게 알립니다.

▸3부모는 다시 실행될 때 값을 읽고 기록을 정리해서, 무한 반복 없이 기다릴 수 있게 됐습니다.

그림은 실제 트레이스가 아닌 코드 기반 시나리오입니다. READY는 실행할 준비가 된 상태이며 즉시 RUNNING을 뜻하지 않습니다. 실제 정리는 list_remove()와 free() 후 status 반환입니다.

자식이 먼저 끝난 경우 / wait의 핵심

자식이 먼저 종료해도, 세마포어에 남은 신호 덕분에 부모는 기다리지 않고 종료 결과를 받는다.

반대로 자식이 먼저 끝난 경우라면 자식이 먼저 세마업을 하고 부모가 세마다운을 하게 될 텐데요.

이 경우에도 세마포어를 이용했기 때문에 신호가 남아서 부모는 잠들지 않고 이어서 진행을 하게 됩니다.

▸1결국 wait의 핵심은 구조체로 종료 값을 전달하고, 세마포어로 부모의 기다림과 자식의 종료를 연결하는 것이라고 할 수 있습니다.

자식 선종료 그림은 현재 코드에 근거한 설명이며 실제 실행 순서를 계측한 자료는 아닙니다. 기존 테스트 원본은 evidence/에 보존했습니다.
