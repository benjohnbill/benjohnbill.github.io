fault 난 주소에서 struct page까지

SPT · hash · page 세 구조체의 연결. 갈림길은 page 안의 spt_elem 한 줄

필드 순서 = week09 include/vm/vm.h · hash 값 = lab/spt-probe 실행 결과 · 청록 = SPT가 엮는 고리 · 빨강 점선 = Hunk 1 이전에 없던 것

1. 누가 무엇을 가리키나

thread → spt(struct hash) → buckets[] → 서랍 list → 힙의 page 안 spt_elem

SPT는 page를 담지 않음 → page는 힙에 따로 · 서랍 list가 page 안 spt_elem만 엮음. 0x401000 = claim 끝(frame·PML4 있음) · 0x400000 = frame = NULL, PML4에도 없음

2. spt_elem · pages가 없으면

청록 고리 전부 사라짐 → page는 힙에 그대로, thread에서 page로 가는 길 없음

0x400000 fault → 커널이 page를 못 찾음 · 종료 때 free할 목록도 없음. frame·PML4 쪽은 1번과 같음 → 두 줄의 일 = page로 가는 길

3. fault 주소에서 page 찾기

내리기 → 해시 → 서랍 고르기 → 비교 → hash_entry. PML4는 보지 않음

내리기 생략 → 키 0x401234는 어느 서랍에도 없음 → NULL (make run EXTRA=-DNO_ROUND). probe의 page에는 operations가 없어서 24 대신 16

4. hash_entry: 고리에서 page로 거슬러 오르기

고리 주소 e − 24 → page 시작. 숫자가 바뀌는 곳은 빼기 한 번

/* include/lib/kernel/hash.h:38-40 */
#define hash_entry(HASH_ELEM, STRUCT, MEMBER) \
    ((STRUCT *)((uint8_t *)&(HASH_ELEM)->list_elem - \
                offsetof(STRUCT, MEMBER.list_elem)))

/* hash_entry(e, struct page, spt_elem): 전처리기가 글자만 바꿔 끼운 모양 */
((struct page *)((uint8_t *)&(e)->list_elem - offsetof(struct page, spt_elem.list_elem)))

lab/hash-probe = hash_elem {next} 하나에 operations·frame 없음 → 거리 8. &(E)->next − offsetof(STRUCT, MEMBER.next) 꼴도 같은 주소: 안쪽 거리 0이 양쪽에서 상쇄 · E에 next 없으면 컴파일 에러

5. buckets 칸과 next 사슬

lab/hash-probe 모양: hash_elem {next} · page {va, spt_elem} · BUCKET_CNT 4. 0x405000 찾기 = find_bucket → 1, 그 서랍만 훑기

7. 찾은 page에 frame 붙이기: page·frame과 두 연결은 언제 생기고 언제 사라지나

page(va)는 SPT 등록부터 프로세스 종료까지 살아 있음 · frame(kva)은 claim 때 생김 · 둘을 잇는 연결은 두 가지 = 소프트웨어 기록(page->frame ⇄ frame->page)과 하드웨어 번역(PTE) · 연결은 eviction 때 끊기고, 두 구조체는 그 뒤에도 남음

세로 = 호출 순서 · 바깥 굵은 막대 = 구조체가 살아 있는 구간 · 안쪽 가는 막대와 음영 = 연결이 살아 있는 구간 · ● 생김 · ✕ 사라짐 · 점선 = 아직 안 짠 단계 · 빨강 점선 = 틀린 버전

그림 2 = pml4_set_page()가 false일 때. 여기까지 생긴 것 = frame(kva)과 연결 ① · 연결 ②(PTE)는 없음 · 두 버전의 차이는 frame 막대가 어디서 끝나느냐 하나뿐

false가 나는 곳 = pml4e_walk()의 세 단계(pdp · pd · pt 표) 중 한 곳에서 palloc_get_page(PAL_ZERO) 실패 · PAL_USER 없음 → kernel pool 쪽 고갈 · 그 호출에서 새로 단 중간 표는 walk가 스스로 반납(allocated) → vm_do_claim_page()도 자기가 만든 것(frame · 연결)을 자기가 치움
