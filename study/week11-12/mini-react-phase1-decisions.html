3. 바뀐 팀 문서

  • ADR 0006 (신규): Patch 형식, path, 순서, 실패, 빈 PROPS, diffViews 인자 검사.
  • ADR 0007 (신규): StateHistory 동작과 이름.
  • ADR 0008 (신규): 검증 페이지. 입력 읽기와 지우는 범위, 실제 영역 기준 비교(DEC-15), 이동 때 편집 버리기, 적용 오류 수습, 기능 테스트 방법.
  • ADR 0005: file 입력칸 제외, createVNodeFromDom은 요소만 받음(DEC-02). ADR 0006: container에는 View 하나, 같은 Patch 재적용은 약속하지 않음(DEC-13).
  • ADR 0004: ADR 0006으로 가는 한 줄. Patch = unknown 단계 종료.
  • GLOSSARY.md: path, StateHistory, 검증 페이지, 실제 영역, 테스트 영역 추가.
  • CONVENTION.md: "형식이 정해지기 전에는 Patch 내용을 읽지 않는다" 삭제 · 동사 get, can, push, back·forward, start 추가 · StateHistory 메서드 이름 규칙 한 줄.

ADR 0005~0008은 모두 status: proposed. 팀 승인은 PR에서: #21 문서 → #22 테스트 → #23 구현 순서로 머지.

4. 실제 브라우저 확인 (Aside, 2026-11-09)

npm run dev로 띄운 페이지에서 실제 키 입력과 마우스 클릭으로 확인. 콘솔 오류 0건.

  • 처음 상태: 두 영역이 같고, 뒤로가기와 앞으로가기가 꺼져 있음 (70~72행).
  • 글자 하나 고치고 Patch: 변경 기록은 그 글자 노드의 characterData 1건뿐이고, li 세 개는 같은 객체로 남음 (74·75행). 로그에 TEXT [5, 3, 0].
  • 바뀐 것 없이 Patch: 변경 0건 (80행).
  • 뒤로가기와 앞으로가기: 두 영역이 함께 바뀌고 버튼 상태가 맞음 (81·82행).
  • 빈 입력: 거절하고 "최상위 노드가 하나 필요합니다"를 표시 (85행).
  • onerror, javascript:, <script> 입력: 아무것도 실행되지 않고 실제 영역에서 지워짐 (88행).

확인하지 못한 것: 실제 한글 IME 조합 중 Patch, 포커스와 커서 유지. 자동화로는 OS IME를 재현할 수 없어 CJG가 직접 입력해 확인할 일.

5. 독립 리뷰 (코드를 쓰지 않은 리뷰어, 2026-11-09)

14건 중 결함 3건은 재현한 뒤 고침. 나머지는 문서와 이름을 고침.

지적등급처리
뒤로간 뒤 바뀐 것 없는 Patch가 이력을 쌓고 앞쪽 기록을 지움 (<p>a<!--x-->b</p>의 글자 두 개가 HTML을 거치면 하나로 합쳐짐)높음입력과 실제 영역에서 주석을 지우고 인접 글자를 합침. HR-N07, HR-N08
type="file" 입력칸에 .value를 써서 오류중간isTextInput에서 file 제외, ADR 0005. T52, P38
적용 중 오류가 나면 이력·화면·버튼이 어긋남중간다시 그리고 안내. V93, V94
ADR 0006에 "container에는 View 하나" 전제가 없음낮음ADR 0006에 추가
Patch와 이동의 비교 기준이 다름낮음DEC-15. V95, V95a
meta·base가 살아남음낮음지움. V88a, 값 중간 javascript:는 V88b
이름·주석·테스트 도우미·문서 표낮음이름 변경, 주석은 이유만, CONVENTION 모듈 표, GLOSSARY 용어 3개

남은 위험: <pre>, <textarea>는 여는 태그 바로 뒤 줄바꿈을 HTML 파서가 버림. 그래서 그 줄바꿈으로 시작하는 글자는 왕복이 정확하지 않고, 뒤로간 뒤 바뀐 것 없는 Patch가 이력을 쌓을 수 있음. 드문 입력이라 남김.

6. 관찰 (결정은 아님)

리뷰 전에는 Patch가 실제 영역 입력칸에 직접 친 값을 보지 않았음. DEC-15로 바뀌어, 지금은 Patch를 누르면 그 값이 테스트 영역의 값으로 맞춰짐. 과제는 사용자의 실제 영역 편집을 가정하지 않음.

7. Lark

Lark 시트는 다빈님 개인 파일로 쓰기로 해서 고치지 않음(2026-11-09 결정). 이 페이지와 테스트 지도가 팀 공유 자료. 시트와 다른 점:

  • CREATE → INSERT (31, 33, 37, 44, 101행). 44행은 코드 쪽에서 patch-insert.
  • 9행 fromdom-skip-whitespace: 코드는 공백 유지(ADR 0005).
  • 3행 fromdom-text, 12행 fromdom-comment-node: 루트가 아니라 자식 사례로 검사(DEC-02).
  • 8행 fromdom-bool-attr: <input disabled>의 기대값은 { disabled: '', value: '' }(ADR 0005).
  • 51행 int-render-roundtrip: 입력 View는 정규형(입력칸에 value가 있고 주석이 없음).
