인스턴스 필드 (인스턴스마다 하나씩)

필드담는 것쓰는 곳읽는 곳
rootComponent감싼 Root Component (예: App)생성자, 한 번 (L45)renderedView() (L103)
hooks상태값. 호출 순서 = 칸 번호READ 첫 렌더링의 초깃값 · WRITE setterREAD useState
container그려 넣는 DOM 요소mount(), 렌더링이 성공한 뒤 한 번update()의 applyPatchesToDom
currentView마지막으로 그린 View. DOM과는 다른 값이다mount()의 렌더링 직후, update()의 patch 뒤update()의 diffViews

전역 변수 (모듈에 하나)

변수뜻사는 기간쓰는 곳읽는 곳
currentComponent지금 렌더링 중인 인스턴스렌더링 한 번renderedView() 시작에 채움 (L100), 끝에 비움 (L116)useState (READ만)
hookIndex이번 렌더링에서 몇 번째 Hook 호출인가렌더링 한 번렌더링 시작에 0 (L101), 호출마다 +1. 끝에 비우지 않는다useState (READ만)
왜 전역인가: useState(0)는 인스턴스도 칸 번호도 받지 않는다. 그래서 "지금 누구의 몇 번째 Hook인가"를 모듈 변수에서 읽는다. 렌더링은 한 번에 하나라 두 변수는 지금 렌더링 중인 것 하나만 가리키면 된다. 사는 기간이 사는 곳을 정한다: 렌더링 사이에도 남는 hooks는 인스턴스, 렌더링 한 번만 쓰는 두 변수는 모듈. 시간표: 레슨 0002.

setter가 기억하는 것

setCount  ──remembers──>  (instance A, slot 0)
click → A.hooks[0] = new value → A.update()

한 사이클 (트리)

FunctionComponent A (instance)
├─ fields
│  ├─ rootComponent = App   <- what to run each render
│  ├─ hooks = [ ... ]       <- values that must survive between runs
│  ├─ container             <- where to draw
│  └─ currentView              <- what to diff against next time
│
├─ mount()  (first render)
│  ├─ currentComponent = A  <- so useState knows whose hooks
│  ├─ hookIndex = 0         <- count calls from slot 0
│  ├─ App()
│  │  └─ useState(0)                         READ
│  │     ├─ slot = hookIndex++  (0)
│  │     ├─ hooks[0] empty -> store 0
│  │     ├─ make setCount, remembering (A, 0)  <- used later on click
│  │     └─ return [0, setCount]
│  ├─ App returns View
│  ├─ createDomFromVNode -> container
│  └─ currentView = View
│
└─ click -> setCount(1)                       WRITE
   ├─ A.hooks[0] = 1        <- uses remembered (A, 0)
   └─ A.update()            <- uses remembered A
      ├─ currentComponent = A
      ├─ hookIndex = 0
      ├─ App()
      │  └─ useState(0) -> hooks[0] is 1 -> count = 1
      ├─ App returns new View
      ├─ diffViews(currentView, new View) -> Patch[]
      ├─ applyPatchesToDom(container, Patch[])
      └─ currentView = new View

깨지는 경우

if 안에서 useState를 부르면 호출 순서가 렌더링마다 달라진다. 뒤쪽 Hook이 앞쪽 칸의 값을 받는다. (Rules of Hooks)
